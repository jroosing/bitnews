# internal/web

The browser UI: server-rendered HTML with htmx, Tailwind CSS and Alpine.js (CSP build), embedded in the binary. Decisions and trade-offs are in [ADR-0005](../../docs/adr/0005-web-ui-stack.md); the milestone design is in [docs/milestones/m6-ui.md](../../docs/milestones/m6-ui.md).

```
internal/web/
  web.go, pages.go, handlers_auth.go  New(Deps), routes, the Page table, login/logout/setup
  middleware.go, errors.go            CSP + headers, _csrf field, JSON-error to HTML, safeNext
  assets.go, render.go, funcs.go      asset hashing + /static/, template sets, template helpers
  icons_gen.go                        generated by scripts/gen-icons.sh (Heroicons)
  src/app.css                         Tailwind source: tokens (@theme), components (@layer)
  assets/static/                      app.css (GENERATED, committed), js/, vendor/, fonts/, VENDOR.md
  assets/templates/                   layout_app, layout_bare, head, nav, components/, pages/
```

## Rebuilding the CSS

`assets/static/app.css` is generated and committed, so `go build` and CI need no Tailwind step. After changing a template, `src/app.css` or `assets/static/js/*.js` (Tailwind scans them for class names), run:

```
make css          # one-off, minified
make css-watch    # while designing
make css-check    # fails if the committed file is stale (not run in CI)
```

The standalone CLI (no node) is downloaded and SHA-256-verified into `bin/tools/` by `scripts/get-tailwind.sh` on first use. Class names must appear as complete strings in a template, JS or Go file: `bg-{{.Colour}}` is never generated. Component classes (`btn-primary`, `badge-ready`, ...) are plain CSS in `src/app.css` and are always present.

Design tokens are CSS variables in the three `TOKENS` blocks of `src/app.css` (light, dark by media query, dark by `data-theme`). Change the accent there, in one place. `TestTokensMeetContrastAA` parses these blocks and fails if a text pair drops below 4.5:1 or a non-text pair below 3:1.

## CSP rules for templates

The CSP forbids inline script, inline style and eval. A test renders every page and fails on any of these, so do not use them:

- no `<script>` without `src`, no `<style>`, no `style="..."` attribute;
- no `on*` attributes and no `hx-on*` (put behaviour in `js/app.js`);
- no `javascript:` URLs; URL attributes take relative paths only;
- progress is a `<progress>` element (never an inline width);
- Alpine: use the CSP build's supported expressions, and reference components registered with `Alpine.data` in `js/app.js`. Never put data (names, IDs) into an Alpine expression: write it into a `data-*` attribute and read it in a method.

Every dynamic value goes through `html/template` escaping. Download names are hostile input. `hx-vals` and similar attributes are built only from server-validated IDs with the helpers below, never from names.

Template helpers: `{{asset "app.css"}}` (hashed URL), `{{icon "name" "size-5"}}`, `{{dict "Key" value ...}}`, `{{attrs "hx-post" "/x" ...}}` (validated attribute list; refuses handlers, style and foreign URLs), `{{hxVals "id" .ID}}` (JSON for `hx-vals`, ID-shaped values only).

## Add a page

1. Create `assets/templates/pages/<name>.html` defining `content` (and optionally `subtitle` and `actions`). The layout supplies the `<h1>` from the page title.
2. Add a `Page{Path, Template, Title, NavLabel, NavIcon, Data}` to `builtinPages()` in `pages.go` (or call `s.addPage(...)` from your own `routes_<name>.go`, invoked from `registerRoutes`). A page with a `NavLabel` appears in the sidebar; without one it is hidden. `Data` returns what the template sees as `.Page`.
3. Page routes already sit behind `UIAuth` and CSRF; an unauthenticated browser is redirected to `/login?next=...`.
4. `make css`, then check the page in the style guide's light, dark and 390 px views.

## Add a fragment or action route (htmx)

Register it in `registerRoutes` (or your `routes_<name>.go`) with `s.handleAuthed("POST /queue/{id}/pause", handler)`. In the handler:

- Services come from `Deps` (add fields to `Deps` as pages need them; `New` only requires the auth services and Settings).
- Render a fragment with `s.renderFragment(w, r, status, "queue.html", "row", view)` where `row` is a `{{define "row"}}` in that page's template. Fragments are swapped in by htmx; the client sends `X-CSRF-Token` from the `<meta name="csrf-token">` tag.
- Redirect with `s.redirect(w, r, "/path")` (HX-Redirect for htmx, 303 otherwise).
- Show a toast by setting `HX-Trigger: {"toast":{"level":"success","message":"Saved"}}`. Levels: success, info, warn, danger.
- A form must also work without JavaScript: give the `<form>` a real `method` and `action`, include `{{template "csrf_field" $}}`, and add `hx-post` for the enhanced path.
- `s.renderError` answers with an error page, or a toast for htmx. Errors from the auth middleware are converted automatically.
- Destructive buttons: put `hx-confirm="..."` on the element (optionally `data-confirm-tone="danger"` and `data-confirm-label="Remove"`); `app.js` shows the styled dialog instead of `window.confirm`.

## Add a component

Components are `{{define "name"}}` partials in `assets/templates/components/*.html`, called with `{{template "name" (dict "Key" value)}}`. Containers that wrap arbitrary content come as `<name>_start` / `<name>_end` pairs, because Go templates cannot take a block argument. Document the keys in a comment at the top of the file, add the component to `pages/styleguide.html` (every state), and add its classes to `src/app.css` under `@layer components` when it needs more than utilities.

Naming: component partials are lower-case with underscores (`empty_state`, `card_start`); CSS component classes are lower-case with hyphens (`btn-primary`, `badge-ready`); Alpine components are camelCase (`confirmDialog`).

Components: `button`, `field` (text/password), `select_field`, `checkbox_field`, `switch_field`, `badge`, `card_start/end`, `empty_state`, `alert`, `auth_banner`, `table_start/end`, `modal_start/end`, `confirm_dialog`, `toast_region`, `progress`, `pagination`, `copy_button`, `csrf_field`.

## Live status placeholders

The top bar has `#live-status` with `#status-down`, `#status-up` and `#status-queue`. The queue work fills them with htmx out-of-band swaps; keep the IDs.

## Static files

`/static/<name>` is served from memory by exact lookup. Templates link `{{asset "js/app.js"}}`, which returns `/static/js/app.<hash8>.js` served `immutable`; the plain name revalidates. CSS `url()` references are rewritten to hashed names at startup. Vendored files and their integrity are listed in `assets/static/VENDOR.md` (`scripts/vendor-web.sh`).
